Project 02 · Advanced Applied Machine Learning

Locally weighted regression, in more than one dimension

A LOWESS estimator that handles multivariate features, adapts its own bandwidth, survives degenerate neighbourhoods, and predicts at points it has never seen — validated with k-fold cross-validation on two real datasets.

Method
Kernel regression, adaptive bandwidth
Tools
NumPy · SciPy · scikit-learn
Validation
k-fold cross-validation

What the first version couldn't do

Project 1 built locally weighted regression from the ground up: weight every training point by its distance from the point of interest, then fit a weighted line through the result. It works, but it has two hard limits. It takes a single feature, and it only estimates at the points it was trained on. Neither restriction survives contact with a real dataset, where you have eight columns and you need a prediction for a row the model has never seen.

This project removes both. The starting point is Alex Gramfort's implementation, which replaces a fixed bandwidth with a smoothing span f; everything below is what had to change to make it multivariate and predictive.

Distance when there is more than one column

With one feature, "how far apart are these two points" is a subtraction. With several, each observation is a vector in a finite-dimensional Euclidean space, and distance is the norm across every feature at once:

d(v⃗, w⃗) = √[ (v₁−w₁)² + (v₂−w₂)² + … + (v𝑝−w𝑝)² ] Computed for every pair of training points, giving an n×n distance matrix.

This is also why the features have to be standardized first. Euclidean distance has no notion of units, so an unscaled column measured in the thousands would dominate every neighbourhood and the weights would effectively ignore everything else.

Letting the data choose the bandwidth

A single fixed τ assumes the data is evenly spread, which it never is. Instead, each point gets its own bandwidth: the distance to its r-th nearest neighbour, where r = ceil(f · n). Where observations are dense the window is narrow and the fit stays local; where they thin out the window widens so there is still something to regress on. The tricubic kernel then maps each scaled distance to a weight, dropping to exactly zero past the boundary.

Keeping the local system solvable

Each point of interest requires solving its own weighted normal equations. In more than one dimension this breaks more often than it does in one: if the points inside a neighbourhood are collinear, or if too few of them have non-zero weight, the matrix is singular and the solve fails outright.

A = XTWX + λI     b = XTWy     β = A−1b λ = 0.0001 — a ridge term, small enough not to bias the fit, large enough to keep A invertible.

That + 0.0001 * np.eye(...) is one line and easy to miss, but without it the function raises on real data. It is the same failure the interactive demo on my homepage shows when the bandwidth is dragged too small: shrink the neighbourhood far enough and there is nothing left to fit a line through.

Predicting at points the model has never seen

The loop produces fitted values at the training points only. Turning those into predictions for a test set means interpolating across the fitted surface — interp1d when there is one feature, LinearNDInterpolator when there are several.

Linear ND interpolation returns NaN for any test point outside the convex hull of the training data, which happens whenever a test row sits at the edge of the feature space. Those points fall through to a nearest-neighbour interpolator, so every row gets a prediction and the extrapolated ones degrade gracefully rather than disappearing.

Validation

Cross-validated on two datasets with genuinely different shapes. In every fold the scaler is fit on the training split and merely applied to the test split — fitting it on the full data first would leak information about the test set into the transformation and quietly flatter the result.

The two numbers are not comparable to each other — the target variables live on completely different scales, so an MSE of 143.91 on concrete strength is not "worse" than 16.84 on fuel economy. Each is only meaningful against other models fit to the same target.

What I would change now

The robustness iteration is incomplete. Gramfort's version computes a residual-based delta and multiplies it into the weights on the next pass, so outliers lose influence. Mine computes delta and never applies it, which means the iteration does no reweighting — and because the residual subtraction broadcasts a column vector against a flat one, delta comes out the wrong shape anyway. Running with iter=1 hides both, since a single pass discards the reweighting regardless.

The fix is small — reshape the residuals and pass delta * w[:, i] into the weighted solve — and worth doing, because robustness to outliers is the entire reason the iteration exists.

Two smaller things: the concrete run uses 2 folds where 10 would give a far more stable estimate, and the data loads from a personal Drive path, so nobody else can execute the notebook as written.
